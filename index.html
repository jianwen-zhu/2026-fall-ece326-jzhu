What you will learn

Python is our common language; programming paradigms are the subject. Starting from familiar C/C++-style imperative reasoning, we examine how a change in representation can change both the program we write and the way we understand it.

By the end of the course, you should be able to:

  • Choose and critique abstractions. Explain when a programming paradigm makes a problem clearer, and what tradeoffs it introduces.
  • Express computation at the right level. Replace element-by-element reasoning with array and tensor expressions, with explicit shapes and reduction axes.
  • Organize state and behavior. Use objects, Python's type mechanisms, and decorators to build reusable interfaces and separate concerns.
  • Make data flow and control explicit. Use iterators, generators, closures, higher-order functions, and continuations to express pipelines, cooperation, and search.
  • Connect expressions to a working system. Trace a small language-model service from input to output and relate its implementation to the abstractions used in class.
  • Evaluate transformations with evidence. Preserve behavior, test equivalence, and measure the consequences for performance and programmer effort.

The notes are executable Jupyter notebooks on GitHub. Follow the sequence or return to a topic as needed. New material is released progressively; this page links only to notebooks verified in the public repository.

01 · Foundations

Learn the language used throughout the course, then look beyond individual statements to sequences and reusable representations.

  • Course introduction — programming paradigms, expressive power, and the course approach.
  • Python imperative core — values, expressions, control, and functions.
  • Python sequences — working with collections, slicing, and sequence expressions.

02 · Arrays as a language

Express many computations at once. Shapes, broadcasting, masking, and reduction become tools for reasoning about algorithms.

  • Array Programming I — array operations and the transition from loops to expressions.
  • Array Programming II — richer array algorithms and applications.

03 · Objects and aspects

Study how interfaces and language mechanisms organize behavior, including the decorator pattern encountered in the lab's HTTP routing.

  • Object-oriented programming — types, objects, protocols, and operator overloading.
  • Metaprogramming and aspect-oriented programming — decorators and separating cross-cutting behavior.

04 · Streams and cooperation

Let data arrive incrementally and computations yield control. Connect these ideas to cooperative execution of multiple agents.

  • Stream programming — iterators, generators, and pipelines.
  • Concurrent programming — coroutines and cooperative scheduling.

05 · Functions and explicit control

Treat computations as values. Progress from closures and composition to continuations, backtracking, and Boolean constraint solving.

  • Functional Programming I — higher-order functions, closures, currying, and expression-oriented programming.
  • Functional Programming II — continuations, explicit control, search, and SAT applications.

06 · Tensors, logic, and probability

Extend the same question—how should this computation be expressed?—to tensor programs, language models, logical reasoning, and probabilistic programs.

  • Tensor programming Forthcoming — Einstein notation and einops for transformations, comparisons, and aggregation.
  • Life of a token — forthcoming. Follow a transformer through embeddings, attention, feed-forward updates, and prediction.
  • Logic programming, model checking, and probabilistic programming — forthcoming. Later-term notes will be linked as they are released.

The course project

One AI service.
Different ways to express it.

Work with a tiny, real language-model inference and serving stack: pretrained TinyStories weights, a NumPy Llama-style model, an HTTP service, and a client-side agent workload. The models are small enough to inspect and experiment with; their purpose is to make the program understandable.

Across four labs, preserve the system's purpose while changing how it expresses computation and control. The language model is the application; programming paradigms are the subject.

Agent workload↔HTTP service↔NumPy model

Lab 1 · From source to service

Run the system end to end, trace the abstractions behind a request, and establish a reproducible baseline. Connect model arrays, program state, and service behavior to observable results.

Lab 2 · From loops to array expressions

Re-express selected numerical kernels using array operations. Make shapes and reduction axes explicit, check agreement with the baseline, and measure the effect on inference. Ordinary NumPy array programming is sufficient for this stage.

Lab 3 · From process to coroutine

Transform a sequential client-side agent into generator-based cooperative tasks. Overlap simulated tool waits using a small scheduler, while preserving each agent's history and the model service's behavior.

Lab 4 · From measurement to optimization

Choose one evidence-backed improvement to the working system. Profile the cost, formulate a hypothesis, preserve the required behavior, and evaluate the result with controlled measurements and an explanation of the tradeoffs.

The question behind every transformation

What meaning stays fixed?
What becomes easier to express?
What changes in the running system?
