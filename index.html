What you will learn

Learning C/C++ makes it natural to think of a program as statements that change state in a prescribed order. This imperative mental model gives us precise control. Yet even everyday programs can be easier to write and understand when we can transform a whole collection, compose a stream of values, or state a relationship without spelling out every step. Programming paradigms give us different vocabularies and levels of abstraction for expressing these ideas.

In this course, we explore alternative programming paradigms that broaden how we think, help us express and reason about computation, and ultimately make us more productive programmers. These ideas also matter at scale: data analytics and AI workloads use abstractions that help expose parallelism and organize computation across many machines.

  • Better ways to express ideas. Programming paradigms are ways of organizing computation, state, and control. Choosing one that fits the problem can improve productivity: less code to write, clearer reasoning, and easier change.
  • Historical gems, one common substrate. APL, Lisp and Scheme, and Prolog provide historical reference points for array, functional, and logic programming. We use Python's multiparadigm capabilities to explore these ideas alongside scripting and object-oriented programming, learning when to use each and why.
  • Modern incarnations, hands-on. See these ideas at work in large language models—from tensor expressions inside a transformer to a running inference service, which uses a trained model to generate outputs. Put them into practice in the labs.

The course project

One AI service.
Different ways to express it.

Work with a tiny, real language-model inference and serving stack: pretrained TinyStories weights, a NumPy Llama-style model, an HTTP service, and a client-side agent workload. The models are small enough to inspect and experiment with; their purpose is to make the program understandable.

Across four labs, preserve the system's purpose while changing how it expresses computation and control. The language model is the application; programming paradigms are the subject.

Agent workload↔HTTP service↔NumPy model

Lab 1 · Trace and measure a working AI service

Run the system end to end, trace the abstractions behind a request, and establish a reproducible baseline. Connect model arrays, program state, and service behavior to observable results.

Lab 2 · Re-express numerical kernels as array operations

Re-express selected numerical kernels using array operations. Make shapes and reduction axes explicit, check agreement with the baseline, and measure the effect on inference. Ordinary NumPy array programming is sufficient for this stage.

Lab 3 · Coordinate agents with cooperating coroutines

Transform a sequential client-side agent into generator-based cooperative tasks. Overlap simulated tool waits using a small scheduler, while preserving each agent's history and the model service's behavior.

Lab 4 · Find a bottleneck and validate an improvement

Choose one evidence-backed improvement to the working system. Profile the cost, formulate a hypothesis, preserve the required behavior, and evaluate the result with controlled measurements and an explanation of the tradeoffs.
